# Подготовка QGIS и исходных данных

Эти действия выполняются до начала основного [гайда](guide.pdf). Для работы нужны QGIS, полигональные данные OSM и приложенный файл зон UTM.

## 1. Установить QGIS

Скачать QGIS с [официальной страницы](https://qgis.org/download/) и установить обычную настольную версию. Скриншоты и последовательность проверены на **QGIS 3.44.15 для Windows**; для максимально близкого интерфейса подходит ветка 3.44. В других версиях названия или расположение элементов могут отличаться.

Отдельная установка Python, PostgreSQL/PostGIS, SAGA или GRASS для описанного маршрута не требуется. QuickOSM и плагины моделирования теней тоже не нужны.

## 2. Включить встроенную обработку

Если отсутствует меню **Processing / Обработка**:

1. Открыть **Plugins → Manage and Install Plugins… / Модули → Управление модулями…**.
2. Перейти в **Installed / Установленные**.
3. Включить **Processing / Обработка**.
4. Закрыть окно и открыть **Processing → Toolbox / Обработка → Панель инструментов**.

Processing поставляется с QGIS как встроенный модуль. Для этого гайда используются штатные алгоритмы QGIS: `Extract by attribute`, `Select by attribute`, `Extract selected features`, `Fix geometries`, `Join attributes by location`, `Split vector layer`, `Reproject layer`, `Extract within distance`, `Merge vector layers`, а также калькулятор полей.

Справка: [QGIS Processing](https://docs.qgis.org/3.44/en/docs/user_manual/processing/intro.html).

## 3. Подготовить локальные данные OSM

### Если GeoPackage уже есть

Нужен файл `russia.gpkg` с полигональным слоем `multipolygons`. В примере использовалась полная локальная база России объёмом около 26 ГБ. Готовая база в репозиторий не включена.

Одинаковое имя файла не гарантирует одинаковое содержимое. Перед началом в таблице слоя должны присутствовать:

- `building` - тип здания;
- `natural` - тип природного объекта;
- `other_tags` - дополнительные теги, записанные строкой в формате HSTORE;
- `osm_id` и/или `osm_way_id` - идентификаторы OSM.

Примеры фрагментов `other_tags`, на которые рассчитаны значения `contains` в гайде:

```text
"addr:housenumber"=>"42"
"building:levels"=>"3"
"roof:shape"=>"hipped"
"building:architecture"=>"stalinist_neoclassicism"
```

Если теги находятся в отдельных столбцах либо `other_tags` записан как JSON, параметры фильтров нужно адаптировать к этой схеме. Готовые тематические наборы GeoPackage от других поставщиков не обязательно имеют структуру из гайда.

### Если подходящего GeoPackage нет

1. Скачать `.osm.pbf` для России или выбранного региона со [страницы Geofabrik](https://download.geofabrik.de/russia.html). Для всей России используется `russia-latest.osm.pbf`.
2. В QGIS временно отключить **Render / Отрисовка** внизу окна, чтобы не рисовать всю карту при загрузке.
3. Открыть **Layer → Add Layer → Add Vector Layer… / Слой → Добавить слой → Добавить векторный слой…**.
4. Выбрать PBF как файловый источник. Если появится выбор вложенных слоёв, добавить `multipolygons`.
5. Нажать правой кнопкой на добавленный слой → **Export → Save Features As… / Экспорт → Сохранить объекты как…**.
6. Указать формат **GeoPackage**, файл `russia.gpkg`, имя слоя `multipolygons`, CRS **EPSG:4326 - WGS 84**. Сохранить все необходимые атрибуты; экспортировать весь слой, а не только выделенные объекты.
7. Дождаться завершения экспорта. Открыть таблицу полученного GeoPackage и проверить поля и формат `other_tags`, перечисленные выше.
8. Дальнейший отбор выполнять по сохранённому GeoPackage. Исходный PBF после успешного импорта можно убрать из текущего проекта.

Это маршрут подготовки через штатные средства QGIS/GDAL. Основной пример со скриншотами начинается с уже подготовленной базы; импорт полной России заново в этом проходе не выполнялся. Обработка большого PBF может занять значительное время и требует места для исходника, GeoPackage и временных файлов. Для первого знакомства можно использовать меньший регион, но контрольные количества объектов будут другими.

Название `multipolygons` описывает слой OSM-драйвера: в него попадают и площадные ways, и отношения, образующие полигоны. Оно не является обязательным фильтром по тегу `type=multipolygon`. Формат `other_tags` зависит от настроек импорта. Справка: [OSM-драйвер GDAL](https://gdal.org/en/stable/drivers/vector/osm.html).

## 4. Подключить GeoPackage в QGIS

1. Включить панель **View → Panels → Browser / Вид → Панели → Браузер**.
2. В Browser нажать правой кнопкой на **GeoPackage → New Connection… / Новое подключение…**.
3. Выбрать подготовленный `russia.gpkg`.
4. Раскрыть подключение стрелкой и добавить `multipolygons` двойным щелчком.

Если раздел GeoPackage пустой, сначала нужно создать подключение. Входной слой для гайда должен иметь CRS `EPSG:4326`.

Справка: [подключение данных в QGIS](https://docs.qgis.org/3.44/en/docs/user_manual/managing_data_source/opening_data.html).

## 5. Добавить зоны UTM

Файл уже приложен: [assets/utm_zones_north.geojson](assets/utm_zones_north.geojson). Его нужно сохранить вместе с гайдом и перетащить в QGIS либо добавить как векторный слой.

Это справочная сетка из 60 полос по 6° для северного полушария, в пределах 0-84° северной широты. Поле `utm_epsg` содержит коды `32601`-`32660`. Сетка используется для назначения системы координат зданиям в данном примере; результаты поиска в ней не содержатся. Специальные исключения зон для Норвегии и Шпицбергена не моделируются.

В шаге 12 гайда следует выбирать именно этот файл. Если на скриншоте показан иной путь, это расположение файла на компьютере, где был выполнен пример.

Для окончательной проверки 10 м применяется **Reproject layer / Перепроецировать слой**. Простая смена CRS проекта или команда Assign projection не преобразуют координаты слоя так, как требуется в этом маршруте. Справка: [Reproject layer](https://docs.qgis.org/3.44/en/docs/user_manual/processing_algs/qgis/vectorgeneral.html#reproject-layer).

## 6. Подложка для отображения карты

Для визуального просмотра можно добавить **Browser → XYZ Tiles → OpenStreetMap**. Подложка используется как ориентир; фильтры и расстояния рассчитываются по локальным векторам. Для онлайн-подложки требуется интернет, для обработки уже сохранённых локальных данных она не обязательна.

## 7. Рабочая папка

Создать отдельную папку для промежуточных результатов, например:

```text
QGIS_guide/
  data/russia.gpkg
  work/
    zones/
```

Можно использовать любое другое расположение, в том числе другой диск. Имена файлов вида `01_apartments.gpkg`, `04_fixed.gpkg` и `utm_epsg_32638.gpkg` в основном гайде помогают отслеживать этапы; в пакетных выражениях важно сохранить описанный шаблон имён.

Сохранять результаты в файлы, а не только во временные слои. Проект `.qgz` содержит ссылки на данные; для переноса проекта должны сохраняться сами файлы и корректные пути к ним.

В комплект для GitHub входят гайд, эта инструкция и сетка UTM. Большие карты, промежуточные базы и результаты расчётов создаются локально и исключены через `.gitignore`.

# Поиск сочетания объектов в локальной базе OSM

Скрипт ищет здание с синей крышей, жилой дом на 4–5 этажей, церковь и фонтан по всей переданной базе России. Он читает подготовленный `russia.gpkg` через SQLite, проверяет теги и расстояния и сохраняет CSV и GeoJSON.

## Файлы проекта

| Файл | Назначение |
|---|---|
| `search_russia.py` | Условия поиска, поиск сочетаний, контроль диска и сохранение результата |
| `osm_database.py` | Чтение GeoPackage и тегов, выбор соседей через RTree, геометрия и расстояния |
| `requirements.txt` | Две прямые зависимости: Shapely и PyProj |
| `.gitignore` | Исключение карт, окружения, временных файлов и результатов из Git |

Оба `.py` должны лежать рядом. Основной скрипт импортирует `osm_database.py`; отдельно запускать этот модуль не нужно. Файлы PowerShell и скрипт сборки QGIS для этого варианта не требуются.

Данные не входят в репозиторий. Сам поиск не скачивает карту, не обращается к Overpass и не конвертирует PBF автоматически.

## 1. Установка окружения

Проверено на Windows с Python 3.13 x64. Открой PowerShell в этой папке (`OSINT/scene-search`) и выполни:

```powershell
py -3.13 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements.txt'
```

Это нужно сделать один раз. pip скачает указанные библиотеки и их зависимости; при установке нужен интернет. После подготовки базы поиск работает без интернета. `.venv` создаётся на каждом компьютере заново.

Проверка установки:

```powershell
& '.\.venv\Scripts\python.exe' -c "import shapely, pyproj; print('Shapely', shapely.__version__, 'PyProj', pyproj.__version__)"
```

Если `py` не найден, установи [Python для Windows](https://www.python.org/downloads/windows/) либо укажи полный путь к установленному Python 3.13 вместо `py -3.13`.

## 2. Откуда взять карту России

Есть два способа.

### Уже есть подходящий russia.gpkg

Перенеси готовую базу отдельно и положи рядом с `.py`. Для сравнения скорости разных компьютеров используй один и тот же файл базы. Рабочий снимок из исходного проекта занимал около 24,54 GiB; это размер конкретного файла, а не гарантированный размер любой выгрузки.

### Есть только .osm.pbf или карты ещё нет

Скачай файл **russia-latest.osm.pbf** со [страницы России на Geofabrik](https://download.geofabrik.de/russia.html). PBF — бинарный формат OSM. Его нужно импортировать в GeoPackage, а не распаковывать как ZIP.

Если уже есть файл вроде `russia-261020.osm.pbf`, повторно скачивать его не нужно. В команде ниже подставь его имя вместо `russia.osm.pbf`.

Для однократной подготовки нужен GDAL с утилитой `ogr2ogr`. В Windows можно использовать GDAL из [установки QGIS](https://qgis.org/download/). Для дальнейшего поиска QGIS не требуется.

Открой **OSGeo4W Shell** из меню «Пуск». Это командная среда с GDAL. Перейди в папку проекта, подставив свой путь:

```cmd
cd /d "C:\path\kb2ctf-tasks\OSINT\scene-search"
```

Положи PBF в эту папку. Если здесь ещё нет `russia.gpkg`, выполни:

```cmd
ogr2ogr -f GPKG "russia.gpkg" "russia.osm.pbf" -t_srs EPSG:4326 -lco FID=fid -lco GEOMETRY_NAME=geom -lco SPATIAL_INDEX=YES -gt 65536 --config OSM_MAX_TMPFILE_SIZE 100 --config CPL_TMPDIR "."
```

Дождись успешного завершения. Команда сохраняет слои GDAL OSM, теги и пространственные индексы в формате, который ожидает скрипт. Подробности: [драйвер OSM](https://gdal.org/en/stable/drivers/vector/osm.html), [драйвер GeoPackage](https://gdal.org/en/stable/drivers/vector/gpkg.html).

При импорте всей России нужны место для итогового GPKG и временной базы — объём может составить десятки GiB и больше. `OSM_MAX_TMPFILE_SIZE 100` задаёт порог переноса временной базы из памяти на диск, а не ограничение расхода диска. Защита диска поискового скрипта на `ogr2ogr` не распространяется. После прерывания импорта частичный `russia.gpkg` не считай готовой базой.

Готовые тематические GPKG из других источников могут иметь другую схему. Для этого кода нужны `multipolygons` и поддерживаемые слои импорта OSM, `geom` в EPSG:4326, поля `fid`/`osm_id`, теги в колонках и/или `other_tags`/`all_tags`, а также RTree-индексы. Простое переименование другого файла не меняет его структуру.

## 3. Запуск

После подготовки локальная папка выглядит так:

```text
scene-search/
  search_russia.py
  osm_database.py
  requirements.txt
  README.md
  .gitignore
  russia.gpkg          # локальная база, игнорируется Git
  .venv/              # локальное окружение, игнорируется Git
```

Запусти из PowerShell в этой папке:

```powershell
& '.\.venv\Scripts\python.exe' '.\search_russia.py' --source '.\russia.gpkg' --output '.\results'
```

Результаты появятся в `results`. Пути в исходниках менять не нужно. В опубликованной копии база по умолчанию ищется рядом со скриптом, а результаты сохраняются в соседнюю папку `results`, поэтому работает и короткий запуск:

```powershell
& '.\.venv\Scripts\python.exe' '.\search_russia.py'
```

База может находиться на другом диске:

```powershell
& '.\.venv\Scripts\python.exe' '.\search_russia.py' --source 'D:\maps\russia.gpkg' --output '.\results'
```

Дополнительные параметры:

```text
--source        путь к GeoPackage
--output        папка результатов
--max-work-gb   порог временных файлов, по умолчанию 2 GiB
--min-free-gb   свободный запас на диске результатов, по умолчанию 10 GiB
```

После копирования базы на диске результатов должно оставаться не менее 10 GiB свободного места при стандартных настройках. Эти пороги относятся к диску и не ограничивают RAM. Скрытый `--_worker` — внутренний параметр; вручную его указывать не нужно. Для остановки обычного запуска используй Ctrl+C.

## 4. Что ищется

1. Есть тег `building`, а `roof:colour` содержит слово `blue` без учёта регистра.
2. Жилой дом: `building=apartments` или `residential`, этажность `4` либо `5`; до синей крыши не более **50 м**.
3. Церковь, собор, часовня либо христианское место богослужения — не более **200 м от жилого дома**.
4. Объект `amenity=fountain` — не более **30 м от церкви**.

Обход начинается с фонтанов: фонтан → церковь → жилой дом → синяя крыша. Соседи предварительно выбираются через RTree, затем расстояния считаются Shapely в локальной метрической проекции AEQD. Для полигонов берутся границы. Ограничения региона и top-N нет: обрабатывается вся переданная локальная выгрузка.

Этажность в OSM — признак кандидата, а не доказательство архитектурного типа «хрущёвка». Данные могут быть неполными; найденное место проверяют по карте и фотографиям. На другой дате выгрузки число результатов может отличаться. Объект может выполнять одновременно роли синей крыши и жилого дома; такие строки отмечены `blue_is_house`.

## 5. Результаты

| Файл | Содержимое |
|---|---|
| `candidates.csv` | Сочетания, идентификаторы, адреса, этажность и три расстояния; UTF-8 с BOM |
| `complete.geojson` | Точки найденных сочетаний |
| `objects.geojson` | Объекты с указанием ролей |
| `footprints.geojson` | Контуры зданий |
| `links.geojson` | Измерительные линии с расстояниями и порогами |
| `summary.json` | Условия, статистика и сведения об исходной базе |
| `partial.geojson`, `conflicts.geojson` | В этой версии создаются пустыми |

CSV открывается табличным редактором, GeoJSON можно открыть в QGIS. Проект `.qgs` этот минимальный комплект не создаёт. В консоли показываются первые 20 сочетаний, в файлы сохраняются все.

## 6. Что хранить в Git

Коммить только два `.py`, `requirements.txt`, `README.md` и `.gitignore`. Карта, её архивы, `.venv` и результаты работы исключены через `.gitignore`. Для проверки после добавления файлов:

```powershell
git status --short
git diff --cached --stat
```

Если Git показывает карту как уже отслеживаемую, `.gitignore` не удалит её из истории или индекса автоматически. В подготовленной папке базы нет и она не добавлялась в Git.
